**New**
- KosmicKrisp now reports shader model 6.6 instead of 6.0 to DirectX 12 and supports 64-bit atomics on Apple GPUs from the M3 on. These are the requirements Unreal Engine 5 with DirectX 12 (Nanite) failed on so far. A UE5 game with DirectX 12 is not tested with this yet.
- DirectX 12 games can use native 16-bit math on KosmicKrisp, which Apple GPUs run twice as fast as 32-bit math.
- Old 32-bit games with DirectX 9 no longer hang on KosmicKrisp when switching to full screen. The cause was a bug in Wine that hit only drivers like KosmicKrisp.
- Fixes a bug from v0.1.0.11: on the first start of Horizon Zero Dawn the loading screen ran at 0.1 fps, because the game waited while loading for shaders still being compiled in the background. Now it runs smoothly, and the game reaches its world.
- Rise of the Tomb Raider, Horizon Zero Dawn and Medieval Dynasty run as before.

**For developers**
- Mesa patch 0031: destroying a shader no longer waits for its Metal build.
- Mesa patch 0030: 64-bit atomics from Apple9 on; Metal only has `max`/`min` without a return value, everything else is emulated (details in `docs/MACOS_PORT.md`).
- vkd3d patches 0009 and 0010: shader model 6.6 and native 16-bit operations on KosmicKrisp.
- Wine patch 0007: win32u queries the properties for placed memory mapping in 32-bit processes through `vkGetPhysicalDeviceProperties2KHR`; the core name is NULL in its Vulkan 1.0 instance. Test program `docs/macos/d3d9-fullscreen.c`.
- vkd3d-proton's test suite runs under MacProton (`meson setup … -Denable_tests=true`, `ninja tests/d3d12.exe`, start with `run.sh --exec`). Before and after the patches the same five tests hang; new failures appear only in tests that were skipped before.
